# UFI Panel Linux：全量迁移与交互实施方案

本方案的目标是把用户提供的 UFI Panel APK 的可观察用户功能完整迁移到 Linux Electron。0.3.0 是现有基线，不是完成版。此次不再以“高级功能打开网页即可”作为原生功能完成条件。

## 1. 范围与证据

- APK：1.10.1，versionCode 87；SHA-256 `ffbcb93f64a9c1aa99a8229f9b90f8121d729eb67f0b8d379fe5eb07501c50d6`。
- 从完整 JADX 输出与已解码字面量归纳到 **43 个 Screen/Dialog/Widget 声明、88 个 /api 路径字面量、115 个功能项**。88 个路径包含前缀和模式专有接口，不等于 88 个可直接调用的独立 API。
- [feature-catalog.json](feature-catalog.json) 为机器可读清单。每项有固定 ID、APK 证据、页面归属、现状、后端条件、验收标准和实施阶段。
- 当前基线：24 项已有实现但尚未完整对齐，29 项部分实现，51 项待实现，7 项需 Linux 等价实现，4 项协议/范围待核实。此统计不是完成百分比，已有入口也不等于完整功能。
- 以上是静态证据清单，**不是已证明穷尽 APK 所有运行分支**。动态构造字符串、反编译失败的协程以及设备能力分支仍需继续核查。新增发现必须追加清单，不能通过修改范围把缺项变成“不需要”。
- 用户已明确：当前仅有 F50 / UFI-TOOLS 可供联调。KANO 可真机验证；GOFORM 直连需确认当前设备原厂入口可访问；ZWRT/datad 和独立模式缺少对应测试环境，必须保留“协议测试 / 未真机验收”状态。

## 2. 桌面信息架构

左侧固定六个主入口；当前主入口的二级导航显示在内容顶部。切换二级页面不改变左侧宽度，不增加更多顶级按钮。设备选择器位于左上；连接状态、全局搜索与任务中心位于顶部。

| 主入口 | 二级页面 | 主要布局 |
| --- | --- | --- |
| 概览 | 设备总览、网络参数、流量统计、设备定位 | 指标与趋势；详细参数列表；日期查询；位置与精度 |
| 网络 | 蜂窝与 SIM、频段与基站、APN、Wi-Fi 热点、LAN/USB、连接终端 | 设置分组；频段选择；APN/终端列表与详情抽屉 |
| 消息 | 短信、转发与通知、通知与执行记录 | 左列表右详情；渠道表单；可筛选事件列表 |
| 工具 | 测速、信令分析、AT/Shell、HTTP 代理、USB 信息 | 长任务工作区；可停靠详情；请求/响应分栏 |
| 自动化 | 定时任务、断网恢复、开机与共享守护 | 列表与编辑抽屉；状态与规则；设备部署向导 |
| 系统 | 设备与连接、设备设置、插件、软件更新、外观与文件、远程管理、客户端设置、关于与授权 | 二级页面较多时水平滚动；按领域展示，禁止单页堆全部表单 |

细则：

1. 功能搜索支持名称、别名、功能 ID；按设备能力显示可用/固件不支持/后端不适用/等待探测。开发阶段的“待实现”仅在功能对照视图中显示，不能把未实现入口伪装成可执行按钮。
2. 同一功能只保留一个领域入口。总览快捷操作复用同一操作控制器，避免出现两个相互不一致的 Wi-Fi 开关。
3. 设置页最多二级分组，单组只保存该组变更；“设备设置”分为常用、电源与性能、连接与调试、认证四个子区，不展示十几张同样的保存卡片。
4. Wi-Fi、APN、语音、短信、基站锁均明确当前 SIM/热点/芯片目标。当前代码里的固定槽位或原始编号需改为后端提供的标签和能力。
5. 本地连接名称、设备别名、本机客户端主题和设备网页主题分别命名，不共用表单。

## 3. 前端层叠与尺寸

“叠放”包括页面排布、可滚动区域及遮挡关系。使用统一层级，不由各页面自行设任意 z-index。

| 层 | 内容 | 行为 |
| --- | --- | --- |
| 0 | 主内容区 | 唯一主要纵向滚动区域；列表表头可吸顶 |
| 10 | 左导航、顶部工具条、底部连接状态 | 不覆盖主内容；分别占据布局空间 |
| 20 | 页面分组导航、未保存更改提示条 | 位于所属工作区内；不能盖住表单提交按钮 |
| 30 | 非阻塞右侧详情区 | 终端、短信、信令详情；与列表并排，保持选中项 |
| 40 | 模态编辑抽屉及背景遮罩 | APN、任务、短信草稿、设备连接；一次只存在一个 |
| 50 | 确认步骤 | **复用抽屉内部步骤或同一个对话框，不在已有对话框上再开第二个模态** |
| 60 | 原生文件选择器 / 系统权限对话框 | 主进程持有窗口和操作令牌；关闭后恢复焦点 |
| 70 | 简短通知 | 不挡底部主要操作；错误保留在相关区域，不能只靠一闪而过的 toast |

- 模态编辑宽度默认 480–560 px；插件代码/HTTP/RRC 查看使用 720–920 px 或独立工作区，禁止在 430 px 窗口里横向滚动源码。
- `1240×800` 为标准验收尺寸；`1024×700` 下列表和详情允许切换单栏。宽屏加大信息区，不按比例无限放大字号。
- 所有模态具备 `aria-labelledby`、焦点约束、Esc 语义、关闭后的触发点焦点恢复。Esc 不能静默丢弃未保存草稿或中止已提交的设备安装。
- 全局只能有一个正在编辑的模态会话。发起新动作时：继续原编辑 / 保留草稿后切换 / 放弃；不得直接替换 DOM 丢掉内容。
- 窗口缩放与 DPI 只改变布局，不改变设备能力判断或后端请求。

## 4. 核心操作流程

### 设备接入和切换

选择模式 → 地址/账号/必要授权 → 测试连接 → 识别版本和能力 → 保存连接 → 进入设备总览。

新连接未验证成功前保留旧连接。每个请求携带本地会话版本；切换后旧结果不能写入新页面。设备上正在安装/重启等操作不能因为切页被再次提交。切换时提示当前设备上的运行任务去向。

Android 独立模式变为“连接远程 Android → 检查 ABI/Root/合法授权 → 选择桥接运行时 → 显示部署计划 → 安装/启动 → 健康检查”。这不是把 ARM 可执行文件放到 Linux 本机运行。官方激活服务是否允许第三方 Linux 接入需核实，不能伪造激活结果或绕过校验。

### 设置保存

读取成功 → 展示原值 → 编辑 → 生成变更摘要 → 按操作影响确认 → 提交一次 → 回读 → 成功 / 部分成功 / 结果未知。

- 常规可逆设置使用行内保存，不连续弹出重复确认。
- 删除、发短信、外部转发、安装/更新、改网/卡槽、Root/工程动作显示明确的对象和影响。复用当前编辑层中的确认步骤。
- 自动刷新只更新监控值，不覆盖脏表单。离开页面保留当前设备草稿；切换到另一设备不带入上一台草稿。
- 超时不等于失败。非幂等动作不自动重试；先回读状态或查询任务，再决定是否允许重发。
- 后端操作成功但回读失败时显示“设备已接受，生效状态待确认”，不能显示“已生效”。

### 列表与详情

APN、终端、任务、插件、短信、日志使用一致的“列表选择 → 右侧详情 → 编辑”模式。查询、排序和轮询保持选中对象。删除最后一条后选择相邻条目；过滤导致对象消失时说明原因，不能把旧详情当作当前行。

短信草稿在内存中按设备/SIM 保存，不默认写入磁盘。批量操作先列出对象数量，返回逐条结果。转发配置密钥具有保持/替换/清除三态，留空不再含糊地代表两个不同动作。

### 长任务中心

测速、OTA、文件上传、导出、信令采集、独立模式部署进入统一任务中心，含任务设备、阶段、开始时间、进度来源和可否取消。

状态统一为 `queued → running → waiting-device → succeeded / failed / cancelled / unknown`。

- 只有后端提供总量时显示百分比；其余显示阶段和已完成量，禁止虚构进度。
- 下载可取消；设备安装阶段不可取消时明确说明。用户切页后任务继续可见。
- 测速停止需关闭所有网络流；信令“暂停显示”与“停止采集”必须分开。
- 程序重新启动只能恢复已持久化的设备任务状态，不能自动重放一次发送/安装命令。

### 后端能力

每项能力必须能表达：`unknown`（未探测）、`available`、`unsupported`（该固件不支持）、`requires-auth`、`requires-root`、`not-applicable`（后端不同）、`unimplemented`（桌面代码未实现）。

不支持显示原因和解决条件；入口不能静默消失。开发清单中的“未实现”也不能被错误包装为“设备不支持”。用户的 F50 不会出现可点的 ZWRT 抓取按钮；功能对照仍能看到该项及其环境要求。

## 5. 实现模块与状态边界

当前 `features.cjs` 与 `features.mjs` 的大分支结构适合作为原型，不适合继续承载全部 115 项。

建议按真实变化点拆分：

```text
src/domain/
  device-session      # 当前设备、模式、版本、能力、会话 epoch
  operations          # prepare / confirm / execute / read-back / result
  jobs                # 长任务生命周期、取消、恢复与订阅
src/backends/
  kano                # 签名 UFI API、代理和任务
  goform              # 官方会话、AD、参数规范化；被 KANO 代理复用
  zwrt                # Bearer、JSON、设备任务、信令流、WebSocket Shell
  standalone          # 远端 Android 桥部署与会话，合法授权/Root 检查
src/renderer/
  shell               # 六组导航、路由、搜索、连接状态
  overlays            # 单一编辑会话、确认步骤、焦点/关闭语义
  workspaces/         # 网络/消息/工具/自动化/系统等页面
```

- 每种 backend 返回统一领域结果，UI 不直接拼 goformId、AD 或设备 Shell。
- 操作先在主进程生成不可变计划，包含设备会话、旧值/新值、目标、影响与有效期；确认只接受计划 ID，不能由渲染器在确认后偷偷替换载荷。
- 长任务用事件订阅推送进度，IPC 只暴露命名动作；不得把任意本机文件路径、Shell 或任意网络代理变成渲染器通用权限。
- 存储：配置与界面偏好可持久化；口令/令牌走 safeStorage；短信内容、NMS 接入码、转发密钥、诊断日志默认不记入常规日志。
- 插件、设备网页、远程终端与地图始终独立隔离，不能获得本地 preload 能力。

## 6. 实施顺序与验收

完整阶段依赖与交付物在 `feature-catalog.json.phases`，不是需要反复征求用户确认的审批清单。

| 阶段 | 交付 | 依赖 |
| --- | --- | --- |
| P0 | 运行态逐页核对、证据、115 项基线与未识别分支 | 无 |
| P1 | 六组导航、统一层级、设备/草稿/任务状态模型 | P0 |
| P2 | KANO + GOFORM 的网络、短信、参数与基础管理闭环 | P1 |
| P3 | 测速、OTA、插件、文件、主题、定位、认证、任务与转发 | P2 |
| P4 | ZWRT 接入、NMS、恢复、记录及共用页面适配 | P1 |
| P5 | 流式信令、RRC/NDJSON、派生分析与导出 | P4 |
| P6 | 独立模式部署、开机动作、共享守护、Linux 小组件等价能力 | P2 |
| P7 | 全量对照回归、打包、安装与迁移 | P3/P5/P6 |

每项至少记录 UI、契约测试、真机读取、真机写入与回读四个独立维度。读取通过不能代替写入通过。没有 ZWRT/独立设备时可完成实现与模拟测试，但 P4/P5/P6 的真机验收保持未完成。

重点回归：切换设备时的过期响应；连接取消；脏表单；相同任务重复提交；未知写入结果；固件不支持；未授权；两个窗口并发编辑；长时采集内存上限；退出程序后的设备任务状态；键盘和小窗口叠放。

## 7. 当前交付物的性质

- `feature-catalog.json`：完整迁移基线与任务映射，不是已经实现的功能列表。
- `INTERACTION-PROTOTYPE.html`：可点击的六组导航、功能搜索、抽屉与单层确认流程，全部使用明确标识的演示数据；不会连接或修改 F50。
- 本方案保留全部已发现功能作为目标。对官方授权服务、特定硬件和缺失测试环境的依赖明确列出，不把它们悄悄删出范围。
