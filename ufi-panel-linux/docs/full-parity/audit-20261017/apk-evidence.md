## 静态分析边界与可复核方式

- 本次直接查阅用户 APK 对应的 `decoded / sources / resources`，来源是 APK 自身；旧分析报告仅用于定位，没有用其结论替代源码证据。
- 原有 `research/scripts/decode-ufi-panel-strings.py` 只还原 `jp3.a(new byte[]{...}, key)` 这类常量 XOR。为排查被分拆赋值遮住的标题，本次还在内存中扫描连续常量 `bArr[index]` 的 XOR；没有执行 APK 代码，也未写回反编译生成物。
- `decoded` 只包含被既有解码器修改过的文件；文件不存在时应查 `sources`，不能把“不在 decoded”当成“不在 APK”。
- JADX 在部分 Kotlin 协程/Compose 代码中有重复块、丢失构造 Map 赋值或错误类型等提示。例如 [ga0.java:388](/home/chnut/文档/ChatGPT/F50/research/ufi-panel-apk/decoded/v7/ga0.java:388) 出现空 LinkedHashMap，却仍有动作和参数名。本文因此只确认明确可追踪的入口、路径和字段名，不依靠异常反编译结果捏造完整请求 JSON。
- 没有运行 Android 逐页点验；没有证明所有条件分支在当前账号/固件可见；没有设备写入/回读验证。APK `assets/sigspec/nr-rrc.json` 或模型中有字段，只是解析能力，不自动等于当前设备实时返回该字段。
- 当前未调用 r2mcp；本次工作是已有 JADX 输出的定向静态复核，无需执行 ARM 库、部署桥接程序或分析激活绕过。
- “未确认”不等于“证实不存在”。如果要把这些项目加入实现验收，需拿到 Android 实际入口或更完整调用链，再对目标模式做对应协议验证。
