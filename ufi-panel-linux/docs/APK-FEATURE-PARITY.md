# UFI Panel APK 与 Linux 功能对照

最新 0.4.0 已落实更多功能，见 [0.4.0 交付记录](RELEASE-0.4.0.md)。下表保留 0.3.0 的历史基线。

基准：用户提供的 UFI Panel 1.10.1 / versionCode 87，SHA-256 见研究报告；Linux 版本 0.3.0。目标设备为已有 UFI-TOOLS 的 F50（KANO 后端）。

0.1.x / 0.2.0 以监控为主，设置功能大多转到网页，不是 APK 功能等价版本。0.3.0 新增原生设置和写入流程，仍不宣称所有 Android 功能已移植。

## 仍有差异

以下是 0.3.0 的现状，不是后续项目的排除项。新的完整迁移范围、交互布局和验收条件见 [全量迁移规划](full-parity/README.md)。

以下没有声称完成，继续通过设备网页或原 APK 使用：

- 独立测速、设备 UFI-TOOLS OTA 下载/安装、主题背景与文件上传管理。
- 终端黑白名单、流量手动校准、UFI/原厂口令修改、USB 协议切换、少数机型专有 NFC/休眠/高级工程设置。
- 地理位置和基站地图、部分调制解调器专有开关。
- 原厂 GOFORM 直连、STANDALONE 守护服务部署、ZWRT 后端和 Android 小组件。这些不属于当前 KANO 客户端支持范围。
- APK 自身账号/试用/激活体系未移植。

## 写入与验证的边界

所有原生写入经命名 IPC、参数校验和本机确认对话框。写操作不会自动重试：超时会提示结果未知，需重新读取状态确认。中兴写入使用有效 Cookie、每次获取的 RD 和大写 SHA-256 AD；同一会话写入串行执行。

插件源码仅作为文本显示，绝不在 Electron 主界面执行。保存前比较设备原有代码摘要，避免覆盖其它网页并发修改。插件仍是设备网页插件，安装不等于在 Electron 原生页面运行该插件。

短信转发渠道保存本身会触发服务端发送测试消息，按钮和确认框明确说明。测试未在真机提交短信、转发、插件安装、锁频、重启、改网或 Shell/AT。真机读取通过不等同于每项写入已经在该固件上执行验证。

参考证据：`research/ufi-panel-apk/decoded/v7/` 中 `rj0.java`（模式）、`s34.java`（热点）、`nf.java`（APN）、`zb2.java`（锁频/锁基站）、`k71.java` / `j71.java`（摘要、编码、会话）；[UFI-TOOLS 固定版本接口文档](https://github.com/kanoqwq/UFI-TOOLS/blob/cf83b815efb114ed026f06dc90550845aafbfceb/API_Doc.md)。
