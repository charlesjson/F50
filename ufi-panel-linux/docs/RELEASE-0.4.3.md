# 0.4.3：短信收发分类

修复旧版将设备返回的所有短信放在同一个列表、只判断未读状态的问题。可运行 `release/ufi-panel-linux-0.4.3-x86_64.AppImage`，无 FUSE 时追加 `--appimage-extract-and-run`。

## APK 的实现依据

分析本地提供的 UFI Panel APK 反编译结果：

- `ge3.java` 定义 INBOX、SENT、DRAFT、UNKNOWN 四个分类。
- `hf3.java` 的 Goform 查询读取 `sms_data_total`，使用 `mem_store=1`、`tags=100`，随后解析每条 `tag`，并不是把查询参数 `tags=100` 当成“仅收件”。
- `nf3.java` 将数字状态 2 / 3 判为发出方向，1 为接收方向；`va0.java` 按方向归类、按 ID 去重，分别展示收件、已发、草稿、其他。通用反编译在文本状态分支有控制流恢复警告，Linux 端仅接受明确文本枚举，不用任意包含 `sent` 的字符串猜测。
- `hf3.java` 的 ZWRT 分支明确将 tag=0/1 归收件、2/3 归发件、4 归草稿、其余归未知。旧桌面适配将 ZWRT tag 覆盖成 unread 的 0/1，会丢失发件方向，本版同时修复。

路径均在 `../research/ufi-panel-apk/decoded/v7/`。本次复用现有反编译结果，无 r2mcp 服务可用。

## 桌面端行为

短信页提供收件箱、发件箱、草稿、其他、全部五个页签，默认收件箱。每条记录标明发件人或收件人以及设备报告的状态。

| 设备状态 | 分类与行为 |
| --- | --- |
| 0 / 1 | 收件箱，区分已读／未读；提供回复；未读项才显示标记已读 |
| 2 / 3 | 发件箱；2 显示已发送，3 显示“发出记录（状态 3）”，不据此推断已送达或失败；提供再次发送，先带入号码和正文 |
| 4 / draft | 草稿；提供继续编辑，发送仍须确认 |
| 不识别或缺失状态 | 其他，保留原始 tag 便于核对 |

发件箱不显示未读筛选和标记已读操作。再次发送只打开编辑框，不立即提交。发送、删除或标记已读成功后使短信缓存失效，重新读取设备记录；不在本地伪造已发送项，也不把“设备接受请求”当成“对方收到”。本版没有新增写回设备草稿的接口。

## 分页与刷新

后端保留设备原始分页查询，并在共享的内存记录集上分类和按 ID 去重。每页显示 50 条当前分类记录，按需继续扫描后面的设备页，避免只过滤眼前 50 条而误报发件箱为空。分类计数以“已加载”或“完整已读取”区分。

每次读取最多扫描 4 个设备页。若当前分类尚未填满且设备还有页，保留已找到的条目并提供“继续查找”，继续同一分类页；不会跳过随后发现的记录。当前会话最多扫描 10,000 条原始记录，达到上限会提示历史不完整。ZWRT 自身返回截断缓存时保留截断提示，不宣称历史完整。

请求失败不覆盖原有列表与页码；失败扫描不提交半成品缓存。快速切换分类时丢弃旧分类的迟到响应。第一分类页随后台状态至多 15 秒重新读取一次，翻阅历史页时保留位置；手动刷新仍可更新当前页。查看、切换分类、复制、打开再次发送均不自动标记已读、不发送短信。

## 验证边界

- 56 项 Node 测试包含分类、发件方向与未读独立、跨页查找、稀疏分类继续扫描、缓存事务与迟到响应、读取上限及 ZWRT tag 保留。
- Electron 交互检查覆盖收件／发件／草稿／未知分类、计数、方向对应操作、再次发送只填入不提交，以及原有短信分页故障恢复和其它功能。
- F50 真机读取了 4 条记录，界面分别显示 3 条收件、1 条发件；“再次发送”只打开并核对编辑框后关闭。未发送真实短信，未修改已读状态。

完整报告保存在 `artifacts/validation-0.4.3.json`；真实短信内容和号码不写入验证报告。
