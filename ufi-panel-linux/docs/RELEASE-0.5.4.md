# UFI Panel Linux 0.5.4

新增「概览 → 历史监控」，将已经采集到的设备指标保存到本机 SQLite，不增加设备 API 请求。可按设备选择最近 1/6/24 小时、7/30 天或任意起止时间，断开连接、关闭窗口到托盘、重新启动客户端后都能查看已保存的数据。

记录 CPU 使用率、内存使用率、CPU 温度、下载/上传速率、当日/当月累计流量、月度上下行累计流量，以及设备提供的 Wi-Fi 终端数、电量和 4G/5G RSRP。没有读数时保存 NULL，零是有效值；流量计数不相加，跨日、跨月清零后保留实际读数。采集失败会记录缺口，暂停、重连和长时间离线会中断曲线。

图表自动汇总为最多约 1,000 个点，各点显示采样平均值，摘要中的最高值直接来自原始采样。流量曲线和表格显示对应时间段末次累计读数。自定义较短时间范围后可切换原始采样，每次最多 5,000 条；表格每页 100 行。支持曲线悬停查看读数、分页查询和独立刷新。

## 负载实测

在本机 Debian 12 构建容器中运行 Rust release 模式、SQLite 3.53.2 的合成数据基准。按一台设备每 2 秒一条、每 30 秒提交 15 条，写入完整 30 天的 1,296,000 条记录；每条包含全部支持的数字指标，数据库包含设备、会话及按设备和时间排列的主键。数据值与字段缺失情况会影响实际体积，以下不是连续运行 30 天的 CPU 占用测量。

| 项目 | 实测 |
| --- | --- |
| 30 天数据库（完成 WAL checkpoint 后） | 119,693,312 字节，约 120 MB / 114 MiB |
| 平均每天 | 约 4 MB / 3.8 MiB |
| 每批 15 条的写入耗时中位数 / P95 | 0.054 / 0.097 毫秒 |
| 加速写完全部 30 天数据 | 10.48 秒 |
| 查询 1 天 / 7 天 / 30 天 | 34 / 161 / 658 毫秒 |
| 每次查询返回的图表点 | 1,000 个 |

对当前默认频率而言，这一负载适合使用 SQLite。历史保存复用现有采集，设备侧没有新增请求；客户端新增一个写线程，写连接缓存约 2 MiB，传输队列和失败缓冲分别限制为 2,048 条。正常仅每 30 秒提交，查询和退出时提交剩余记录。按同样的数据密度估算，连续一年约 1.46 GB / 1.36 GiB；每秒一条的空间需求约加倍。

查询使用独立只读 WAL 连接，在后台依次读取所选范围并聚合，内存不随整个原始数据量增长，也不阻塞采集进程或窗口事件循环。查询耗时随命中采样数量增长。长范围图表限制的是返回点数，原始采样不会因汇总而被删除。

## 保存与使用边界

- 位置为 `$XDG_CONFIG_HOME/ufi-panel-linux/telemetry.sqlite3`，默认 `~/.config/ufi-panel-linux/telemetry.sqlite3`，权限 `0600`。SQLite 静态链接到客户端，不增加数据库服务或 Node.js 原生扩展。
- 只保存数值、设备名称/服务地址、接入模式及采样会话。不会保存登录口令、令牌、Cookie、IMEI、短信内容或原始 JSON。
- 记录按「接入模式 + 规范化服务地址」区分；修改名称会沿用原历史。更换地址会建立新的历史设备，同一地址更换硬件则继续记录在该地址下。
- 原始记录长期保留，不设置自动过期。历史从新版开始记录，不能补回安装前的数据。
- 采集在客户端连接设备且未暂停时进行。关闭到托盘继续采集；真正退出客户端或断开连接后停止。
- 正常退出会提交尚未写入的记录；强制终止可能丢失约最近 30 秒的缓冲。`synchronous=NORMAL` 在系统断电时也可能丢失最近提交，数据库事务仍保持原子性。
- 写入错误会提示且自动尝试恢复；缓冲有上限，避免磁盘异常导致内存不断增长。写入失败时仍尝试查询已经保存的数据。

## 验证

常规检查：

```sh
npm test
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
npm run dist
npm run test:history
npm run test:interactions
```

可显式重跑 30 天基准；测试创建临时数据库，结束后删除，不改动用户历史：

```sh
cargo test --release --manifest-path src-tauri/Cargo.toml \
  history::tests::benchmark_history -- --ignored --nocapture
```

数据库测试覆盖重启持久化、不同设备隔离、重复采样幂等、空值与零、流量清零、失败/暂停/重连缺口、时间边界、索引、原始采样上限、WAL 并发读写、退出补写及数据库打开失败后的恢复。WebKit 用本地模拟设备检查图表、原始表格、悬停、断开后查询和完整重启，不向真实设备发送写操作。

测量与界面验证文件位于 `artifacts/history-benchmark.json` 和 `artifacts/tauri-history-validation.json`。
