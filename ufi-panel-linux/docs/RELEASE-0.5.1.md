# UFI Panel Linux 0.5.1

2026-10-16（Asia/Shanghai）。此版本新增设备插件中心与应用内插件设置窗口。

## 使用

连接 KANO / UFI-TOOLS 设备后，进入「系统 → 插件」。默认显示设备上实际安装的插件；插件市场单独加载，不影响已安装项目。

- 猫猫与 OpenSSH 的「设置」会打开原生网页并定位到相应控件。首次打开可能需要在设备网页登录。
- 猫猫另有「代理面板」，默认连接设备 7788 端口，也可填写独立的反代面板地址。
- 未适配的旧插件提供「原生设置」入口，在完整的设备网页中使用。
- 「管理」支持修改单个插件的源码、启用、禁用与删除；所有本地写入先展示确认。
- 「高级编辑」保留整段自定义内容编辑功能，兼容历史未分组代码。

禁用和删除改变前端插件注册，不会自动卸载或停止设备上的 SSH、代理等服务。原生插件设置中的操作沿用插件自身的实现与确认方式。

已安装列表在连接成功、提交插件操作、回到插件中心或窗口重新获得焦点时刷新；插件中心打开时每 15 秒检查一次，短期内重复读取会复用缓存。设备端修订变化会关闭过期设置窗口；切换设备和断开连接会关闭旧设备页面。

原生设置窗口失去焦点或隐藏时，通过设备网页自己的刷新按钮暂停状态采集，回到窗口时只恢复本窗口主动暂停的采集；用户原先手动暂停的状态不会被重启。这针对原生 UFI 状态轮询，第三方插件自己的后台任务仍遵循插件行为。

备份下载保存在系统下载目录，文件名带随机标识，避免覆盖已有文件。关闭设置窗口会销毁对应网页；按设备连接分隔网页登录会话。

## 实现

`src/core/plugins.cjs` 负责原生起止标记解析、禁用包装、逐项修改、修订检查与设置目标。写入只替换目标片段；未知、破损、嵌套标记和历史源码保留原样。同名更新必须明确选择目标，不再静默追加重复脚本。发送前检查设备的 5 MiB JSON 大小上限。

`src/renderer/plugins-ui.mjs` 提供已安装与市场两个视图。设备脚本只作为文本预览与编辑，不在本地主界面执行。`src-tauri/src/device_pages.rs` 管理独立设备 WebView、导航范围、已适配面板的新窗口和下载路径。设备网页没有本机接口权限；主界面的 CSP 继续禁止 iframe。

同窗口右侧内嵌 WebView、通用设置 manifest 与统一风格的本地表单仍属于后续阶段。

## 验证

全部验证通过：67 项 Node 测试、2 项 Rust 测试、8 组插件原生交互检查及 11 组既有功能回归。汇总为 `artifacts/validation-0.5.1.json`。

测试记录与截图保存在 `artifacts/`：

- `plugin-device-readonly.json`：对真实 F50 的只读查询，已识别猫猫 TProxy 与 OpenSSH，并生成对应入口；没有修改设备配置。
- `tauri-plugin-validation.json`：隔离容器中真实 WebKitGTK 的插件交互验证。
- `tauri-plugin-center.png`：插件中心界面截图，使用模拟设备数据。

运行 `npm test`、`cargo test --locked --manifest-path src-tauri/Cargo.toml`、`npm run test:plugins` 和 `npm run test:interactions`。原生界面测试使用独立 Xvfb、Tauri WebDriver 和测试用 X11 输入，写入只针对本地模拟设备。备份、文件上传与窗口操作在此环境验证，真实 F50 仅验证插件发现。

设备保存接口不支持原子条件写入。客户端在提交前重新读取并检查修订，能拒绝已发生的其他端修改；多个管理端同一时刻提交仍存在竞争窗口。
