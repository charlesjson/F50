# UFI Panel Linux 0.5.2

2026-10-16（Asia/Shanghai）。修复在本机 WebKitGTK 2.54.1 中打开原生插件设置后，背景滤镜引起的页面渲染内存持续增长。

## 事故与定位

20:23，内核记录 UFI Panel 应用组发生系统级 OOM。被杀的 `WebKitWebProcess` 当时约有 19.5 GiB 匿名驻留内存；systemd 记录整个应用组的内存峰值为 49.7 GiB，交换空间峰值为 56.5 GiB。用户当时打开过猫猫／OpenSSH 设置。

另外，20:31 的 `run-p215127-i215128.scope` 是诊断程序的独立测试组。它配置了 1 GiB 上限，触发的是 cgroup 内存上限，随后被内核终止。这与 20:23 的全系统 OOM 是两个事件。后续诊断改为 2 GiB 隔离上限，并在更低的阈值主动终止测试页面，避免再次触发内核上限。

对照测试使用本机 WebKitGTK 2.54.1 和同一真实设备页面。即使不加载客户端注入脚本、不加载插件源码，页面仍可出现快速增长；单独禁用普通 JavaScript 是不可用的规避方式。保留页面脚本、图表和插件，只在浏览器渲染层禁用 `backdrop-filter` 后，内存增长恢复正常。这将触发条件定位到原生页面背景滤镜与当前 WebKitGTK 渲染实现的组合；尚未取得 WebKit 内部分配栈，不能把具体上游缺陷编号视为已确认。

## 修复

- 设备网页、插件设置与设备弹出面板，先创建空白视图，安装用户级兼容样式，再导航到目标地址。
- 兼容样式只禁用背景毛玻璃 `backdrop-filter` / `-webkit-backdrop-filter`，覆盖子框架与伪元素。
- 保留普通 `filter`，因此 IMEI 等字段原有的内容模糊不会被移除。
- 样式仅作用于客户端内的设备 WebView，不向设备保存主题设置；在 Chrome 等浏览器访问原生页面时保持原有外观。
- 插件设置仍使用原生功能，启用、配置、上传、备份与面板入口保持可用。

此次修复不是把进程内存上限调大，也没有要求用户减少其他应用占用。受限诊断上限仅用于复现环境。

## 验证

测试覆盖本机真实 WebKitGTK 下的持续内存观测，以及隔离容器中的原生交互回归。报告保存在 `artifacts/validation-0.5.2.json`，其中区分了真实设备只读页面检查与模拟设备写入测试。

前一版容器内短时功能测试通过，未能发现本机渲染路径的持续内存增长。此次增加本机同版本引擎的对照与持续观测；持续测试通过不等于能够保证任意第三方插件永远没有内存问题。
